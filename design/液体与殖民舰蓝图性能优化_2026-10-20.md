# 液体与殖民舰蓝图性能优化（2026-10-20）

玩家反馈：舱内出现液体后严重掉帧；ARK-01 殖民舰进入场景后，打开蓝图严重掉帧。第二项针对蓝图使用，不是殖民舰切换加载时间。

## 修改

- `scripts/liquids.gd`：合并前预计算半径，排除尚不能合并的新滴与冰球，每个网格只收集一次邻居，距离比较使用平方。保留原候选次序、体积、动量与合并条件。
- `scripts/liquid_rounds.gd`、对应 shader：水、冷却液及冰球共用一份 MultiMesh；上传位置、体积对应半径、年龄、相位和表面法线，GPU 计算原来的波动与附着形状。保留原 10/16/24 点轮廓、液面高光、冷却液内环，以及冰球的七个切面与两条内纹。
- `scripts/liquid_draw.gd`：其余液体、喷流与霜花保持原样式及绘制次序，合并三角形提交。保留正线宽、圆弧采样及折线接头。
- `scripts/blueprint.gd`、`blueprint_dashes.gdshader`：虚线的相同短段缓存为网格；GPU 按缩放调整宽度。保留每个对象与文字的覆盖次序。逐条缓存 TextLine，避免大量唯一标注挤出字体缓存后反复排版。标签避让使用空间索引，保留候选位置顺序和相交判定。剔除视野外图形与文字，平移视野时更新；四像素边界余量覆盖摄像机亚像素缓动。

没有降低 320 液滴上限、120 Hz 物理配置、分辨率或抗锯齿，也没有删掉蓝图里的对象和标注。其他种类液体混入时采用通用批量绘制路径；没有声称所有种类、任意数量的泄漏都保持相同帧率。

引擎行为核对：Godot 的正宽度 `canvas_item_add_multiline` 会逐段调用画线；[RendererCanvasCull 源码](https://github.com/godotengine/godot/blob/4.7-stable/servers/rendering/renderer_canvas_cull.cpp)。字体的字符串绘制使用内部排版缓存；[Font 源码](https://github.com/godotengine/godot/blob/4.7-stable/scene/resources/font.cpp)。

## 同机真实渲染采样

Windows / GTX 1080 / Godot 4.7 / D3D12 Forward+ / 1600×900。关闭垂直同步及帧率上限；`--fixed-fps 60` 只固定模拟步长以保持前后状态一致，不是把实际渲染帧率锁定 60。资源预算限制新进程树为 4096 MB，所有重测试串行执行。

液体场景使用 MF-126 的 CT 冷却液罐和舱内泄漏；压力输入达到 320 滴预算，前后同一随机种子、相同模拟帧数，采样结束均剩 178 滴。旧的液体性能检查把大部分液滴放在船外真空，不能代表这次反馈的场景。

| 场景 | 修改前平均 ms/帧 | 修改后平均 ms/帧 | 修改后 P95 |
|---|---:|---:|---:|
| MF-126，无泄漏 | 6.22 | 5.81 | 7.18 |
| MF-126，真实切开冷却液罐，18 滴 | 7.46 | 6.74 | 8.57 |
| MF-126，舱内密集冷却液 | 52.41 | 17.04 | 23.23 |
| ARK-01，蓝图关闭 | 28.98 | 28.36 | 33.19 |
| ARK-01，蓝图打开动画 | 130.04 | 60.77 | 89.49 |
| ARK-01，蓝图全景稳定 | 94.72 | 36.90 | 43.56 |
| ARK-01，全景缩放第一段 | 129.11 | 56.31 | 63.96 |
| ARK-01，全景缩放第二段 | 130.07 | 56.24 | 62.06 |

新增当前版本近景和平移检查：蓝图近景平均 26.44 ms，平移平均 29.40 ms。这两项没有修改前同条件采样，因此不报告优化百分比。

密集冷却液平均帧耗时下降约 67%；液滴绘制提交从 23.79 降到 0.78 ms/帧，合并从 10.76 降到 5.96 ms/帧。蓝图全景稳定帧耗时下降约 61%，全景缩放下降约 56%。ARK-01 不开蓝图也约 28 ms/帧，本次没有解决其全部场景成本，不能声称全景稳定 60 FPS。首次打开蓝图仍有约 157 ms 峰值，包括首次建立缓存；不能把平均耗时改善说成没有首次打开停顿。

原始日志：`proofs/liqbp_before.log`、`proofs/liqbp_final.log`，以及对应 `*_budget.json`。

## 验证

- `tests/liquids_check.gd`：14 项通过，覆盖切管泄漏、漂移、表面附着、飞溅、合并、低温沸腾、真空结冰、真空燃料不被激光点燃、BL-88 爆球和 DR-150 泥浆。原船外 309 滴检查为 1.27 ms/步。
- `tests/fire_check.gd`：20 项通过，包含燃料、氧化剂接触反应，以及电弧和推进器点火。
- `tests/notes_check.gd`：7 项通过，工程笔记仍只记录实际检查过的内容。
- `tests/liquid_blueprint_visual.gd`：7 组双 SubViewport 真实渲染对照通过，涵盖水/冷却液、冰球混合、多种液体，以及殖民舰蓝图 0.03/0.3/1.0 缩放和不改变缩放的视野平移。与冻结的修改前绘制逻辑比较，所有组均无大于 1/255 的像素通道差异；0.03 缩放均值差异为 0.00001/255。
- 同一视觉检查另含 320 滴、4 次连续合并前后对照，得到的液滴字典完全一致，覆盖不同液体、年龄、附着、冰球、相对速度与多次合并。
- `git diff --check` 通过。真实渲染测试、性能采样、燃烧测试无脚本或 shader 错误。液体回归和笔记回归退出时分别仍报告 ObjectDB 32 / 40、资源 16 / 20 的清理信息；本轮没有把退出清理列为已修复项。

`tests/liquid_blueprint_reference.gd` 冻结了必要的旧绘制和合并函数，仅供回归比较。`tests/liquid_blueprint_perf.gd` 可以复测性能。截图和完整日志位于 `proofs/`。

本次交付为源码修改及自动化验证，没有重新导出旧 Windows EXE，也没有把自动检查描述为人工游玩验证。
