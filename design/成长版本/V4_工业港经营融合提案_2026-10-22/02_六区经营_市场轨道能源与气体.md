# V4-02：六区产业规格——船市、监管、轨道、能源、气体、加工与货运
状态：待评审细化稿。原则：使用已存在的船舶物理、损伤/压力与熔炉系统，不创建与真实资产脱节的假资源。

## 一、船舶市场与贸易港（trade）

### 1. 两个不同法律业务，不能混淆
- **受托拆解**：船东保有产权；合同明确服务费、允许回收/不得动的设备、违约条款和安全要求。沿用现有 Market.offer / Career.active，旧档可继续完成已签合同。
- **废船购买**：玩家成为船主；支付买入价、检验/交易费、拖运、作业和处理成本，拥有购买合同明确包含的回收物。不自动享有原船上第三方扣押/租赁的设备，登记必须披露。卖/用/储存回收品取决于产权。
- 后续可扩：**残骸回收权**（有限处置权，不等于完全船舶产权）、工业原料现货与加工订单、设备交易、外部仓储与拖船服务、长期供货协议。
- 不把“合同三选一”删除：作为开局基础公开委托与紧急救济小单保留；新增统一可筛选列表/持续船源和可选工业需求。初期 8–15 艘持久挂牌为体验目标，数值依性能调节；无需在一帧里生成全部飞船物理实例。

### 2. 资产的一生必须连贯
listed(挂牌) → reserved(可选保留) → purchased / contracted(成交/受托) → awaiting_pickup(等待拖船) → transit(在轨航次) → holding(本地待泊) → berthed(进入某泊位) → working(拆解中) → settled(已结算/资产关闭)。
购买只改**资产所有权和仓储/运输订单**；不能直接调用生成船到 dock。每船唯一 asset_id，船型+厂号+损伤变体种子，防止同船在两个泊位或市场重复出现。
货物/设备交付要追踪原资产与回收记录，避免盗卖未归属第三方的部件。

### 3. 卖家信息博弈：真实状态先确定，广告只能观察或撒谎
- ActualState：基于船文件、事故变体和实际系统状态一次确定，购买后**不得因随机营销脚本再改变**。
- SellerClaim：卖家声明（可有意删减、模糊词句、过时数据、局部真实/整体误导），带来源、发布日期、责任与可信度。示例“动力正常停机”不等于“电容无残压”；“整体结构完好”不能保证局部无补焊。
- RegulatorRating：第三方仅给 1–10 综合评分 +机构标识+日期+证据覆盖率/检查方式；评分是对真实状态有误差的**观测**，不等于状态、收益率或风险概率。部分评分可能来自敷衍或串通、存在利益关联，但**应可调查追踪**（同一机构异常高分、报告矛盾、退款与纠纷）。
- BuyerInspection：购买前支付费用换独立检验/复检，结果是有限传感器证据；不会透视封闭船体、不会免去进坞重新测压测电、不会给全船事故坐标。
- 商业证据结果：玩家可保存检测记录，在虚假声明被证明后申请索赔、下架评级机构或影响商业信誉。发生索赔要有先前留存合同与证据，不能为金钱提供可刷漏洞。
- **公平性约束**：先生成固定 ActualState，再让卖家/监管对它进行部分观测或撒谎；所有错误可以在事后解释（记录来源、有效期、逻辑），禁止“玩家买了才摇事故”；监管系统不默认多数是腐败，否则评级失去意义。
- 先做 3 种诚信卖家 + 2 种评估质量，未来再加复杂商业调查，不要一开始建几十个 NPC 和法庭 UI。

### 4. 可见利润与商业抉择
结算前估算：预期回收价值区间（不是神谕） - 买入价 - 检验费 - 拖运费用 - 拆解人工与设备耗损 - 电费 - 危险处理费 - 仓储与售卖手续费 - 时间占用机会成本。
玩家可选择受托低风险、直接买入、独立检验后买入、待轨道窗口再买/保留，且每条都有可计算代价。市场报价有买卖价差、买家限量和合约交付条件，不能无成本反复倒卖。
贸易港的旧“售价 +10%/+20%”“星级权重”可暂保留在过渡期；新市场上线后逐步转成更低手续费、更高市场覆盖率/证书可信度/优先买家及更高级资产渠道，避免叠加无限加价。

## 二、拖船站与轨道运输（tug）

### 1. 两层物理精度，彼此不能混为一谈
- **小行星带太阳轨道层**：同一个日心参考系内的位置与速度随游戏时间推进，船舶拥有轨道参数/时间戳。初期用稳定圆/椭圆二体轨道传播；轨道图必须显示当前站点与挂牌船舶的轨道、当前位置、预计转移轨道和交会时间。
- **本地港区层**：接近站后的相对运动、减速/速度匹配、拖船与废船进港、排队和泊位交接。小尺度继续使用真实 Godot 2D 物理，不把几百万公里压成主场景里一条可随意飞过的线。
- 外部航次采用工程近似的自动规划器：出发窗口、总 Δv (m/s)、推进剂需求、航行时间、拖船额定牵引质量/推进能力、交会余量；“最省燃料”和“最快到达”是可选择路线，不保证永远存在合法的最优解。
- Δv 单位是速度增量，不能拿地图像素距离除以一个常数计算；质量/推进剂依有效排气速度的火箭方程或经标定的物流估算。船舶质量含残余内容物，拖运重心与姿态限制在入港场景体现。
- 轨道与时间快进必须在同一权威 game_clock 下更新订单与库存，不能只把飞船图标前移而忽略生产时钟。
- 经济与节奏：长期航次可以快进到安全事件，不强迫玩家实时等待；近期运行的短程回收业务优先出现在新手市场。所有航次保留外包选项，付费更高但不阻断发展。
- 现实近似需标记：不把小行星带画成天然密集岩石海；规划器数值在外部单元测试中验证轨道传播、交会相位和守恒，不能靠画面看着像轨道就算完成。

### 2. 拖船站运营
拖船是有身份的资产：功率/推力等级、最大安全拖载、推进剂和耗能、状态/维护、正在执行任务与 ETA。
业务：为自购船提货、为他人提供运输服务、为大型工程做特殊拖运；多个拖船共享到港窗口/待泊容量。级别收益是可用拖船数量、单船载荷、可靠性、同时航次，不再只是取消 $1,500 费用。
航次状态：planned → waiting_window → outbound → coupling → towing → approach → delivered/failed。出问题应报告谁、在哪一步、因为什么，不随机吞掉资产。
拖船站交付给 cargo/holding 真实待泊列表；空坞前不强制开下单。已有 G6 大船“排队一单”在完整航次上线后迁移为真实队列，避免同时扣两重等待。

## 三、动力区与真实全港电网（power）

### 1. 基础量纲及设备注册
- power_capacity_MW = 发电机组可用功率；每设备 standby_MW、active_MW、peak_MW；line_limit_MW = 区域输电限额。
- storage_MWh、soc_MWh、charge_MW、discharge_MW 表示可放电总量与速率：例如 1 MWh 储能不等于能无限期提供 1 MW 以上供电。
- 统一设备 PowerConsumer 通过现有实例/区域注册：无人机充电器、吊机、搬运机、第二回收口、熔炉（现有 smelter.gd 额定逆变器约 24 MW，可复用作为标定基准）、气体压缩/低温设备、货运装卸、拖船服务和中央环。
- 临时超载由优先级调度、储能补足、减少生产速度或自动推迟低优先级订单解决；**不是全站强制断电、玩家坠亡**。基础机、紧急照明、返航、危险监控优先保电。
- 若某工艺因断电而存在安全隐患，必须定义真实停机安全序列，不能在功率不足时瞬间冻结到安全状态。

### 2. 玩家决策
首次：低供电只够拆船；开炉则需停部分设备；中期储能实现峰值并行；后期修复主电源/母线/冷却让熔炉、气液、二泊位一起工作。
电网 UI 显示未来生产排程、MW 当前需求/峰值、MWh 可持续时间、限流/跳闸对象、修复所需物料；用户可以设置优先级并授权临时超载（风险可见）。
动力区对外岸电是可选业务，卖出冗余电力需占用真实供电预算，不允许先卖电再当自己也有那份电。
现有 port stage 一二阶转为“发电/配电容量+实际可用接口”，原 power_ok 硬前置逐渐替换/封装为容量检查，旧存档自动映射，不能让已购买吊机突然失效或凭空丢失。

## 四、加工区：材料、气体与工业产线（process）

### 1. 保留现有熔炉
现有 smelter.gd 已模拟高功率加热、炉料、冷却、液钢、倾炉、浇铸等。不要另造“虚拟熔炉”跳过既有加工物理。将现有炉内环节对接批次库存及电网，成熟配方可以自动排产。
G5 原配方：废料 → 合金，原文标称 1:0.7（工程初期平衡提案，需审：损耗去哪、能否以真实质量/残渣项记账）。工程合金附加电子料配比待用户审，不可凭空发明永久配方；外购废钢同样可进炉，不强制经过拆船区。
材料产出：工业废料、合金、电子料、复合料、气液等；保留完整设备仓库和型号/完好度，拆设备为材料应不可逆且留下消耗记录。不能让完整设备又卖又拆又装。
加工生产按游戏时间/批次更新；运行中的关键熔炉物理可视化与大事件操作保留；禁止数千个持续运动的货物 Rigidbody。

### 2. 气体是有成分、有来源、有品质的实体资源
源头复用 atmos.gd、systems.gd、tanknet.gd、liquids.gd 与容器已配置内容物。对每个舱/容器以一套可审计的成分质量/摩尔数记录：
- O2、N2、CO2、H2O(v)、污染/其他组分；专用推进剂和氧化剂**保持独立危险物类型**，绝不一律混成普通空气。
- 局部压力/温度/体积/气体数量依状态方程或现有引擎守恒模型计算，流量按压力差/阀门/管路转换，历史读数与真实状态保持分离。
- 气体抽取分成“释放/排放”“混合气压缩入罐”“净化”“按品种分离”“压缩或液化”“质检出库”。每一步有设备容量、分离回收率、能源耗用、时间、污染去向与储罐容积。
- **不要因为名字叫空气就提供固定 21% O2 收益**；实际混合物可能缺氧或含燃料蒸气、污染物、极端温度。传感器不能隔舱透视。气体分离只按可测/可处理样品进行，防止抽取前后无中生有。
- 氧气只有符合质量标准才能卖给生命支持客户；工业级、液氧氧化剂客户与可呼吸供气不能混为一个无条件商品。氧气助燃，低温液氧罐需要材料、隔热和防混物；污染物必须有处置路线/费用，不应因为卖不掉就允许不受限排放到内部作业区。
- 气液库存至少按 kg（气体）与批次品质/温度/纯度/来源管理；液体产品另按 kg/t，必要时显示体积。**不要用“抽了 100 m³ 空气→库存 100 m³ 高压氧”这类不守恒转换**。
- 少量舱室空气可能只值极少钱，应允许便宜处理；中大型空气库、工业气罐和外部原料才支持批量生意。氮气也有惰化/冷却买家，价值由需求和加工成本决定，不是固定垃圾。
- 后期扩展：利用水净化/电解制取 O2 与 H2，必须支付原料和能量并处理氢气储存；不作为第一版必做项。

### 3. 工业产出多用途
每一批原料/成品都能选：出售现货、按指定工业订单交付、留作港区建设、继续加工；外部市场价格取决于有限的买卖深度、质量与需求。精炼的利润应扣原料买价/机会成本、电费、损耗、仓储/运输；不允许任何配方无成本生钱。
加工区不只提供原有 scrap_k 加成，改成可见的产能、效率、配方资格、炉位与产品质量；旧 scrap_k 可以在迁移期保留为经营声誉/减少损耗的一次性兼容效果，但不能叠加成无限重复倍率。

## 五、货运区（cargo）：仓储、派送、交付
- 入库凭证源于“真实已通过回收口的货物/实体设备”或“外部市场实际交付的货物”，每件保留来源资产、数量、品质、所有权；抽象库存是过了真实交付边界之后的表现。
- 仓位按 bulk metal t、sealed electronic crates、complete equipment volume/mass、gas tank compatible volume、dangerous segregated capacity 分开，容量不足应清楚提示并允许合法替代，而不是让掉进仓库的实物蒸发。
- 生产批次由货运自动从已存在库存调拨到加工线，受每周期吨数/装卸功率/队列占用限制；普通调拨成熟后自动化，超大件/危险品仍需人工规划。
- 出口端必须区分**成交合同**（trade）和**实际交货**（cargo + ship），交货未发生不准领款；可以经营外部仓储/卸货服务，但会真实占用空间与装卸设备。
- G6 原货运区“加工具槽、自动补耗材”保持旧版兼容，其经营主收益应转向实在仓储/吞吐量/货物类型能力。

## 六、商业合同与价格的最低防滥用规则
1. 原料/产品总质量有去向：进入下一工序、运输损失、残渣/污染物、卖出或自用；每笔交易唯一 transaction_id，重载不重复出货。
2. 现货市场有买卖价差、限量需求、实际到货和到账时序；不能无尽地从同一商人低买高卖。
3. 受托拆解服务费与自购船的最终回收产权严格分离；卖家评级不能被拿来当实际风险阀值。
4. 产业调度使用同一个游戏日历，离线不要求真实墙上时间开着电脑；允许在安全状态跳过合理时段。
5. 常规业务中断不等于死局：可购买外部拖运/岸电/物流服务作为贵但可用的替代；保留免费基础拆船单和基础无人机。

## 七、第一版只做哪些？（避免一次把 Codex 淹没）
MVP: 持久 8–12 船舶列表 + 一艘买入后有资产 ID + 一种卖家声明与监管 1–10 分 + 一次有 Δv/ETA/费用的拖运 + 实际入坞 + 普通废料生产一批标准合金 + 商业出售一批 + 两类负载争抢电网 + 可回收一批有实际 O2/N2 比例的混合气并进行合理储存/出售。
暂缓：监管黑幕大剧情、复杂航天交会器手动控制、太阳系几十个市场、全自动跨站舰队、完整钢铁厂布局、所有气体低温化学流程、宏观动态竞品产业、多人经济。宁愿上述 MVP 形成一个可靠的 20–30 分钟游戏循环。
