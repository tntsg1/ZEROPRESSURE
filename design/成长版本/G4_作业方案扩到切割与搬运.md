状态：开工中（2026-10-21）。本文件是 G4 的完整需求，有改动以本文件为准；用户提修改意见后同步更新。

## 目标与假设

- 目标：同型号第二艘船的重复手动操作占比从现在的 69–73% 降到 50% 以下，而切割路线、危险处理、完整取件的决策仍由玩家做。
- 验证假设：第二艘轻松了，但没有“看机器玩”的无聊；暂停原因一眼看懂；自己想亲手做的部分没有被机器抢走。

## 现状

- 作业方案（scripts/plan.gd）已有控制、切割和搬运的记录/执行入口，同型号按 P 运行；灰鹭另有基础安全处置预置方案。现有预置不等于完整拆解自动化。
- 最近审查 `proofs/growth_review_plan.log` 为 13 项、5 项失败，首船录制 0 刀、人工比较 0%→0%，不能证明切割搬运闭环或降低重复劳动。先修正真实场景验收，再按修订稿扩展。

## 要做的

### 1. 记录切割步骤
- 玩家每完成一刀（一条激光笔划穿过一块零件），记录：零件的出厂编号（船文件里的 key，没有 key 的零件按 tag），切口折线（零件本地坐标，相对零件原始框架），当时的新鲜读数（同现有规则），以及这块零件两侧舱室的压力读数（像开门那条规则一样强制要求）。
- 只记录“安全的刀”：这一刀没有引发事故（失压、起弧、泄漏、爆燃、切坏完整设备）才写入；引发事故的刀不记，且从那一刀起本单停止记录（沿用现有前缀规则）。
- 切到完整设备的刀不记录（方案不替玩家做“切不切设备”的决定）。

### 2. 记录搬运步骤
- 一个自由体进入回收口时记录：它包含的零件编号集合、进的回收口类别（设备口 / 熔炉 / 危险品口）。
- 只记录玩家亲手送或标记给机器送的；漂进去的不记。

### 3. 重放
- 切割：按记录顺序，找到同编号零件（必须仍在船上、没切过），检查前置读数（新鲜、不比当时危险）、两侧舱室压力 ≤ 5 kPa、零件没有带压容器或带电线路穿过（用现有 on_cut_into 的判定预检）。满足则机器切：沿记录折线执行 game.cut_kerf（和激光同一条路径），每刀占用机器时间 STEP_TIME × 折线长度系数。
- 搬运：当一个自由体的零件编号集合与记录匹配，自动标记给搬运机 / 吊机送到记录的回收口（≤1.5 t 搬运机，≤12 t 吊机，更重暂停请玩家）。设备口的件走设备口，这是记录的一部分。
- 暂停条件新增：零件不在（这不是同一艘船）、零件已被切过、舱室仍带压、零件上有带电线路或带压容器、没有能搬的机器。暂停时 HUD 写明是哪块零件、缺哪个读数。
- 重放的切割和搬运计入操作日志的“机器”类（machine），不算玩家手动。

### 4. 玩家保留的
- 切不切完整设备、危险系统的处理、第一艘船的全部切割路线。
- 任何时候 J / P 停机；玩家亲手切了方案里的零件，方案跳过那一步。

### 5. 界面
- HUD 方案状态行显示当前步骤类型（阀门 / 切割 / 搬运）和目标零件。
- 结算页“作业方案”行显示本单新记录了多少刀、多少次搬运。

## 数据与存档
- Career.data.plans[ship_id] 的步骤新增 {"do": "cut", "key", "pl": [[x, y]…], "pre": […]} 与 {"do": "haul", "keys": […], "zone"}。
- 零件要带出厂编号：Model.Piece 加 key 字段，建船时写入，存档保存。
- 老方案（只有控制步骤）照常可用。

## 自动验收（tests/plan_cut_check.gd）
1. 作业艇干净拆一单：方案含控制步骤、≥N 刀、≥M 次搬运。
2. 第二艘作业艇按 P：机器完成记录的刀与搬运，0 事故；操作日志里机器类占比显著高于第一艘，玩家手动占比 < 50%。
3. 舱室带压时在对应的刀前暂停并说明；读数过期暂停；零件被玩家先切掉则跳过。
4. 带事故的刀不写入方案；切到完整设备的刀不写入。
5. 存档往返：记录中途的方案与重放进度一致。

## 不做
第二泊位自动执行、多机协作授权、方案编辑器。

## 你要审
两侧舱室 ≤ 5 kPa 的自动切割门槛保留。完整设备运送须沿玩家已授权的用途与目的口执行；工程预留对象不得同时卖掉。结算以交付、工程能力和下一目标为主，机器操作比例作为辅助数据。新的验收与待实施顺序见修订稿第 9–10 节。
