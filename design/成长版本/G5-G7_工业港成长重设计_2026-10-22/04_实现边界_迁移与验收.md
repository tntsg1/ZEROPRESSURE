# G5–G7 实现边界、旧档、统一时间与验收

状态：未来开发规格，**本文件列的是需要做的检查，不是本次已经运行的结果**。接口名字均为建议，不宣称项目已有这些 API。

## 1. 现有系统怎样复用

| 现有系统 | 保留的事实来源 | 后续挂接 |
|---|---|---|
| market / career | 旧合同、资金、签约规则 | 新资产市场、订单、权属；旧合同适配而非删除 |
| world / model / ship | 实际工件、形状、连接和实例 | 资产 ID 与船内件/物理实例绑定 |
| plan | 实际录制工序、安全检查、人工接管 | 设备预约与泊位上下文，不允许后台另造假执行器 |
| work_orders | 实际完整交付、工程奖励、留用/售卖互斥 | 新工业需求复用凭证与事务模式 |
| dock / hauler / crane / scrapline | 实际搬运、限重、交付边界 | 收货凭证与设备占用事件 |
| smelter | 炉内实际料、温度、过程、出钢与铸造 | 炉次与商业批次适配，不新建平行倒计时炉 |
| atmos / systems / tanknet / liquids | 舱内与容器实际介质、危险、管路 | 同一组分账与商品质检，不用商业库存改写压力 |
| port / port_art | 区域 ID、旧建设阶段、场景与施工 | 能力映射、紧凑实体几何、业务现场；由统一设施定义派生绘图/碰撞/接口，不只补装饰 |
| save / career settlement | 原子保存、备份、结算防重 | 扩展多资产事务，保留旧结算保证 |

各层只通过已经定义的交接事件入账。不能在动画开始、机器派单或工件进入摄像头时就发货/领钱。

港站的统一设施定义、实体与后景分层、真实碰撞/通行、载具流程、公司业务和同尺度美术验收，按 [07 实体港站与工业美术验收](07_实体港站与工业美术验收.md) 逐项执行；本文件的迁移、物理证据和性能检查与该专项标准共同构成出口，不能只做其中一部分。

## 2. 最小状态与身份

建议每个独立领域有明确 schema 版本；主 Career 保留兼容外壳。不要先实现一个包含所有未来功能的巨大管理器。

| 对象 | 最少字段 |
|---|---|
| ShipAsset | asset_id、船型/厂号/变体种子/生成版本、产权、状态、位置、实际状态引用、泊位实例引用 |
| Listing | listing_id、asset_id、卖家、报价/有效期、可见声明/报告、交易状态 |
| TransportMission | mission_id、资产/货物引用、拖船 ID、路线快照、承诺 ETA、推进剂/费用、阶段 |
| InventoryBatch | batch_id、质量/组分/品质/温度、权属、来源凭证、储位、已预留量 |
| Equipment | 现有实例 ID、原船/来源、型号/完好度、权属、安装/仓储/交易状态 |
| ProductionJob | job_id、实际炉次/设备 ID、输入预留、已投料量、产物/废物凭证、阶段 |
| DeliveryOrder | order_id、合同快照、需求/剩余量、预留货物、装运与验收凭证、付款状态 |
| PowerGrid | 源、线路、储能、负荷、策略、当前积分状态 |
| BerthContext | berth_id、asset_id、物理状态、合同/作业计划、权限、机器预约 |
| LedgerEvent | event_id、原因、前后状态/数量、相关对象、提交状态、可重试键 |

同一资产任一时刻只能处于一个实际位置。市场显示历史成交记录不等于仍可购买；在途资产不能同时生成在船坞。

UI 的公开查询与 ActualState 的内部查询分开。防信息泄露指游戏可见性设计，不伪称离线单机存档具有客户端保密能力；玩家修改文件不是评级系统要解决的问题。

## 3. 交接边界与防重

### 买船
检查资格/资金/报价有效→准备资金与产权变更→同一事务写入→成功后更新 UI。失败保留可重试订单，不吞钱不留半艘资产。

### 入港
航次完成→本地待泊占位→确认泊位与通道→创建唯一物理实例→保存交接完成。生成过程中崩溃重载必须恢复同一次交接，不再复制一艘。

### 实体收货
回收边界确认实际吞入或接收→用稳定工件/交付 ID 生成凭证→撤销现场可重复交付身份→生成对应钱/库存/设备去向→保存。

生产阶段、输送过程和现场撤销的提交点需要按现有机制具体实现并做故障注入。禁止先销毁物体再试着保存钱，失败后无从恢复。

### 加工与交货
预留不是消耗。投炉或实际进入加工设备时记消耗；阶段产物对应原始输入与加入物。装货可预留，离库/交付按实际运输边界处理；客户验收再付款。退货/残次按合同处理，不神奇回到原配方原料。

### 建设与安装
原料/设备检查→预留→实际施工过程→阶段验收→设施能力激活。现有已付建设先保留；不为补动画而再次收费。若首版仍使用离散施工，必须诚实标明边界，不能声称已实现全程实体施工。

事件使用防重键，必要状态有快照；不无限保存逐帧日志。压缩/归档只能在已提交检查点之后进行，必须保留未完成事务与必要索赔证据。

## 4. 统一游戏钟与快进

### 唯一权威时间
运输、生产、订单到期、仓储和电网都从同一模拟时刻计算。暂停菜单冻结模拟；默认退出游戏不继续计费、不推进合同期限。渲染帧率不决定生产速度。

### 三种推进方式

| 模式 | 可以做什么 | 不能做什么 |
|---|---|---|
| 现场正常运行 | 固定物理步长运行真实作业与危险 | 仅靠动画帧数计产量 |
| 现场受限加速 | 经性能/稳定性验证后，用更多完整固定步推进 | 增大 dt 跳过碰撞、读数或危险过程 |
| 安全经营跳时 | 无必须连续模拟的现场任务时，分事件积分运输/安全生产/费用 | 把正在切割、悬吊、泄压、失稳的物理场景直接跳到完成 |

第一版不实现尚未证明安全的现场高速加速。若有现场作业，玩家可以等真实机器工作，或在安全断点暂停它再跳时；不能擅自替玩家按暂停而隐藏影响。

熔炉只有在“等效安全离散模型”通过与细步运行对照后才支持经营跳时；之前按真实炉体推进，不以新倒计时替换。热损失、能源、产物必须一致，不能后台冷炉秒炼。

跳时按最早事件分段：供能变化、储能耗尽、订单到期、运输抵达、储罐上限、工艺异常。到事件时停止并更新全部相关系统；不先把所有货物生产完再补算停电。

危险事件打断快进的提示必须说明谁、何时、为什么。无法跳时时显示具体阻塞项和安全处理方式，不只说“现在不能”。

## 5. 双层空间与轨道

远程以日心参考系的轨道状态、时间戳和版本化传播模型表示；本地港区用相对坐标和 Godot 物理。两层通过交会和本地接近边界连接。

只做现阶段需要的航线规划，先限制已验证轨道族；不虚构任何相位都可用的“霍曼快车”。路线报价依实际可行解、载荷/推进能力和费用模型，失效报价必须重算并让玩家知情。

已承诺 ETA 在读档后不因市场随机数变化而重新抽取。路线模型更新要兼容在途旧航次快照；不能中途把原燃料预算改成不够用。

正式轨道实现前需要专项依据与数值验证，不把本设计文档视为航天算法规格。禁止把港区装饰轨道直接当太阳轨道模拟已完成。

## 6. 旧档迁移

### 保护顺序
实际原文件只读采样与哈希→复制至测试私有路径→旧版解析→迁移预览→新格式写临时文件→校验→原子替换私有目标→重载验证→第二次迁移验证幂等。

正式版本只在符合现有备份规则后迁移用户档；禁止自动降级覆盖高版本存档。当前活动合同若需要旧规则，先保留签约快照，安全回港时再完成相关转换。

### 迁移映射

| 旧状态 | 新状态 | 禁止事项 |
|---|---|---|
| 已签受托合同 | 保留受托身份、已定费用与权益 | 改成自购并再次收款 |
| 旧三张 offers / held | 兼容委托/已排队报价 | 原排队丢失或重复罚等待 |
| 完整设备与自有出勤装备 | 原实例、数量、完好度与用途保留 | 用“新版资格”顶替真实自有工具 |
| G4 计划/局部作业包 | 原数据保留、旧格式适配、必要时明示重新授权 | 静默删库、跳过旧安全约束 |
| port 已建阶段 | 明确映射为已付能力与施工完成状态 | 回收已付设施或再收同一笔钱 |
| structure_t 可用余额 | 按定义转换为可用废料或明确的建设余额 | 把历史总回收量当未花余额再发一次 |
| 旧贸易/加工售价权益 | 迁移期保留，转服务权益前给等效清单 | 新旧倍率同时无限叠乘，或静默剥夺 |
| 旧 power 硬前置通过 | 新容量下保留合法已购能力的最低可用基线 | 更新后所有吊机突然停用 |
| 待播施工/已付未完成项目 | 原付费和状态保留 | 动画重播触发二次扣款/奖励 |

没有证据区分“历史已消费”与“现有余额”的字段不得猜测发放，先查实际写入语义。旧档本来有债务就保留，没有就不能新增。

## 7. 每版测试矩阵

下表为**待实现测试规格和建议日志名**。未创建的脚本/日志不能出现在报告的“已通过”清单。

| 门槛 | 自动检查/声明夹具 | 必须真实运行的检查 | 真人体验 |
|---|---|---|---|
| G4 前置 | 格式与旧计划兼容 | 实船 A 录刀与交付，实船 B 安全重放，正数基线与人工减少 | 接管与提示是否可信 |
| G5.1 | 批次分割、库存预留、防重、写盘失败 | 真实回收/进炉/成品/装运/收款 | 留货与加工是否值得 |
| G5 现场前置 | 载具权限、控制恢复、可达性与旧档映射 | 实际乘车；小艇驾驶、靠泊、释放无人机、返回；短路线与基础四区现场 | 是否真正改善通行，愿不愿意使用载具 |
| G5.2 | 所有权状态机、固定船况、路线数值对照、评级事件防重 | 地图联动、实际运输、唯一实例入坞、检测对应、失实评级案例、资产转售 | 信息能否帮助选择，经验是否有价值 |

| G6.1 | 坐标/旧阶段映射、设施实体清单、机械状态保存 | 实际墙梁/门/机床接触、全尺寸通行；实乘/实驾/靠泊；六区业务与连续机械；同尺度美术对照 | 像真实工业站还是背景；与拆船是否同样硬核精细 |
| G6.2 | MW/MWh 积分、调度、储能、事件快进对照 | 实际炉体/吊机负荷、失电安全、应急返航 | 瓶颈有趣还是琐碎 |
| G6.3 | 组分平衡、纯度、危险分类、低温/蒸发模型、到离港时序 | 实抽、分离、实际液化与储存、合格低温交接、客户靠泊/验收/付款；污染/满罐/失电检查 | 能否理解排放或回收的选择，过路船补给是否形成完整生意 |
| G6.4 | 合同限量、采购权限、吞吐与利润 | 至少两条非拆船业务实际交付 | 自动业务能否省心 |
| G7.1 | 预约死锁与防重、泊位隔离 | 两实际泊位并行、碰撞、异常接管/存档 | 警报是否过多 |
| G7.2/3 | 项目付款/取消/重入、尺度校核 | 整舰入坞、双环动力、核心危险、阶段回收 | 会话是否可控、结局是否有成果感 |

建议日志分别使用 `proofs/g5_*`、`proofs/g6_*`、`proofs/g7_*`，独立记录版本、脚本、种子、存档夹具、执行参数、检查总数/失败数、退出码、资源统计。失败日志保留，不覆盖成同名成功证据。

### 证据分级

1. 单元/规则检查：可用声明的纯数据夹具验证计算和事务。
2. 场景夹具：可用声明的全尺寸载荷检查碰撞/路径，不冒充整船流程。
3. 真实物理端到端：实际输入、实际工件、实际机器与交付，不删件、不传送、不预置成果。
4. 原生渲染/交互：真实 UI 操作和可见状态；截图不证明物理或性能。
5. 人工试玩：验证乐趣、清晰度、重复劳动与节奏。AI 自动化不能替代这一级。

任何报告必须逐项标注证据类型。自动通过不自动变成“玩家已经觉得好玩”。

## 8. 性能与导出

- 以有渲染的原生候选包测 1080p；记录机器、渲染后端、窗口模式、画质、限帧/同步设置、采样范围和至少 120 秒稳定区间。
- 目标持续 60 FPS；候选帧时间门槛 P95 ≤16.67 ms、P99 ≤25 ms。加载/切场尖峰单列，不能删除作业中的卡顿样本。若项目已有更严门槛，沿用更严者。
- 同时报告 CPU、GPU/渲染可用指标、物理体/接触数量、内存与场景规模。`--fixed-fps 60` 只表示模拟推进方式，不证明每秒实际渲染 60 帧。
- 场景至少包括：大型船近看、蓝图开关与缩放、液体泄放、真实回收拥堵、港区全景、双泊位与生产/物流并行。重测用户曾反馈的卡顿入口。
- 碰撞、液体、图纸、港景分别定位；可做不可见静态绘制缓存、按需更新、远程资产非刚体化，但不能降低活动载荷真实碰撞来通过。
- 重型测试串行运行，沿项目资源限制与预算包装器；测试私有数据与用户数据分开。
- 相关自动与物理门槛通过后才导出候选包，再验证包内资源、正常启动、旧档副本继续、端到端关键链与包内性能。源工程通过不等于 EXE 已验证。
- 人工试玩未完成时可交付“候选”，不能写该版本完整完成。

## 9. 接下来实际开发的顺序

1. 按用户 2026-10-22 最新要求开工 G5：接受机械臂应急穿模取货及较低结算，不再以 G4 全项通过阻塞后续开发。G4 红色门槛、迁移/变体/安全/性能等遗留继续记录并行处理；不伪称 G4 全绿，不把本目录当已完成清单。
2. G5 先完成关键通行路线与基础接驳/小艇现场样片，同时选定 G5.1 首个需求和真实原料去向；不以全港美术重做阻塞，也不以“已能开菜单”代替现场。
3. 加船资产、有限市场信息、轨道图与运输闭环，完成 G5.2；包含实际失实评级案例和有成本的资产转售。
4. 三路比较与升级反馈真人验证，关闭 G5 出口问题。
5. G6 扩展完整六区现场与载具用途，完善电网，再把气体回收、液化和过路船补给做成完整产业；允许分段验证，不删减该完整出口。
6. G7 双泊位先过小中型船并行和共享资源，再做重载工程与整艘远航者。
