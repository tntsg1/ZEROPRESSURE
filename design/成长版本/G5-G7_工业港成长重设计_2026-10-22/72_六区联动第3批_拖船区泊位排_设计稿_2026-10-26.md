# 72 六区联动第 3 批：拖船区泊位排

日期：2026-10-26。依据：69 号第四节；用户定案 Q4 C、Q5 A、Q13 C。状态：已实现，自动检查通过；真人试玩未做。

## 做法

| 项目 | 以前 | 现在 |
|---|---|---|
| 拖回来的船停哪 | 船坞右边的待拆泊位（会压到货运栈桥），第二艘往下排 | **拖船站外的露天泊位排**：拖船站左侧开阔空间，一个一个往上排；每个泊位有系泊架和编号“拖船站泊位 N · 船号” |
| 能停几艘 | 不限 | 拖船站 0 / 1 / 2 阶：**1 / 2 / 4 个泊位**；在路上的、到港的、扣在港口的都占位 |
| 泊位满了 | — | 星图和终端的派拖船按钮变灰，写“拖船站泊位满了（n / n）：先拆掉一艘，或扩建拖船站”；二手船市买船同样挡住 |
| 能拖多长 | 只看船坞长度 | 另看**拖船站等级**：0 阶（租来的旧拖船）44 m，一阶 88 m，二阶不限；拖不动的写“拖船拖不动 x m 的船（现在最长 y m）：先修拖船站” |
| 谁去拖 | 拖船站修好后有自家拖船，运费一样 | 自家拖船（TG-1 / TG-2）**待命且充满电**时由它去，**运费减半**（只算电费和损耗）；否则外包拖船去，全价 |
| 拖船充电 | — | 自家拖船拖完回港电量归零，在拖船站充电：电网上 3 MW 一艘（拖船站这一组），满电约 60 秒；电少就充得慢；星图和终端写“TG-1 充电 63%” |
| 开工 | 合同开场把船从船坞右边推进来 | 合同开场先把船**从它的拖船站泊位**绕过港站推到船坞口（约 6 秒），再照旧推进船坞 |

- 旧的“大船排队一单”规则（G6，用户第二轮试玩点名看不懂）在新主线下关掉：拖船站泊位和拖船等级已经管住了大船。
- “自己开作业艇挂缆推船、省推送费”（Q13 C 的“以后”）这一批没做，留到作业艇牵引做完再接。

## 八条对照

①派拖船的地方（星图、终端、二手船市）挡住的规则和说法一样；③泊位、拖船出航 / 充电 / 待命都写在星图和终端；⑤泊位满、拖不动在点之前就写明原因；⑦先派哪艘、等自家拖船充好电省一半运费还是马上外包，由玩家选；⑧每个泊位画编号和船号，不用记哪艘在哪。

## 实现结果（2026-10-26）

- 新文件 `scripts/tug_yard.gd`（`class_name TugYard`）：`slots / max_len / can_tow / taken / full / block / assign / slot_px`，充电 `charge / charging / ready_tug / came_home / advance`，状态行 `status`。
- `scripts/ship_market.gd`：`tow_find`、`buy` 先查 `TugYard.block`；自家拖船待命时运费减半并记下 `asset.tug`；到港时分配泊位（`asset.yard`）、拖船记为没电；`find_fee` 给出现在派船的实际运费。
- `scripts/tug_fleet.gd`：出航的拖船按 `asset.tug` 认，外包的不占自家拖船。
- `scripts/grid.gd`：充电中的拖船是拖船站组的负荷（3 MW）。`scripts/game.gd`：每帧充电，充满时提示。
- `scripts/tow_traffic.gd`：到港过场的终点、停泊的船、出发的拖船都改到拖船站泊位排；画系泊架和编号。
- `scripts/game.gd`：合同开场 `yard_start()` 从泊位推出（`PUSH_T` 6 秒），镜头跟着船身中间。
- `scripts/star_map.gd`、`scripts/terminal.gd`：派船按钮写“派自家拖船 TG-1 去拖 · 半价”或挡住的原因；底下一行泊位与拖船状态。
- `scripts/market.gd`：新主线下不再给大船打“排队”标记。
