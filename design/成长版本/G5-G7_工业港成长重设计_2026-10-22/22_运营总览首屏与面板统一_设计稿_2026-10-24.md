# 22 · 运营总览首屏与面板统一（第三步）

日期：2026-10-24。状态：**已实现并通过自动验收，待用户试玩。** 依据：V4《对话》第十二节“零压港运营中心”、12 号 §5（统一总览负责日常查看与调度，各区保留专业终端）、Q29、Q49（常规消息不抢操作或镜头）、Q53（总览默认走时）；用户口味“讨厌反复点击”“硬核工业，不要 AI 味”。本稿开工前写，有改动以本文件为准。

## 要解决的
- 回到空船坞按 B，第一眼是 8 个应用大磁贴，看不到港口在干什么；要知道炉次、在途货、客户缺口、下一个建设目标，得翻四五个页面。
- 后加的五个原生面板（交易行、炉台、分选台、六区业务终端、目的地单）各是各的样子：深黑底 + 一条细边 + 灰按钮，和船坞终端的工业 HMI（铭牌、凸起面板、指示灯、数码读数、分段量表）不是一套。

## 做什么
1. **`scripts/ops.gd`（新，纯数据）**：`Ops.cells(game)` 给四格，`Ops.decisions(game)` 给待决策事项，全部读真实存档与现场：
   - **港区电网**：动力区阶段、四台高耗能设施接电数、当前实际负荷（炉体实时功率 + 分选驱动 240 kW 在转时）、待缴电费。没有电网容量模型（G6.2），不编“余量 8 MW”，写明“容量计量待 G6.2”。
   - **船舶运输**：交易行成交在途批次（待发 / 装货 / 运输中，分进出）、排队大船、拖运费、作业艇停在哪个泊位。
   - **拆船泊位**：在手合同 / 空闲、船坞长度、十六项修缮完成数、市场报价张数。
   - **加工生产**：分选批次、炉次状态，仓库公司库存总吨数。
   - **待决策**（最多 5 条，危险 > 待办 > 机会排序，每条一句原因 + 去处）：欠缴电费；炉次等你到炉台亲手测温出钢；客户订单缺口（还差 X t，仓库有 Y t）；可承接的客户订单；排队大船已到可接；仓库有未分选金属可去分选台；有合格炉料且有客户缺口可开炉；在途货到港；钉选 / 下一个建设目标还缺什么；贷款本期应付超过现金。
2. **船坞终端首页**：顶部读数与目标条不动；正文上排四格大读数（铭牌 + 指示灯 + 两三行真实数据，点一格进对应专业页：电网 → 零压港·动力区工程，运输 → 交易行，泊位 → 合同页（不可接时修缮页），生产 → 交易行·工业客户）；中间“需要你决策的事项”逐条可点；底部 8 个入口缩成一排紧凑键（图标 + 编号 + 名称 + 一行状态）。现场类事项（炉台、分选台）点了不跳页，在终端里给出位置与按键说明。
3. **空船坞 HUD**：左上角一条四灯小条（电网 / 运输 / 泊位 / 生产）+“待决策 N · B 终端”，不弹窗、不抢镜头，合同场景不显示。
4. **`scripts/ops_skin.gd`（新）**：共享皮肤。主题（字体、按键、数值框、下拉、表格、页签都换成终端同款），`OpsSkin.pane()` 右侧栏（Hmi 面板色 + 凸起边 + 顶部色条），`OpsSkin.Plate` 铭牌标题（设备编号 + 名称 + 状态灯），`OpsSkin.Readout` 读数格，`OpsSkin.Section` 分节线。
5. **五个面板改用皮肤**：业务终端、炉台、分选台、目的地单改用 `pane + Plate + Readout`；中央转运环业务终端直接画四格 + 待决策（同一 `Ops` 数据）；交易行保持全屏布局，换成终端同款顶栏（铭牌 + 现金读数）、凹槽面板与表格样式。所有按钮文字、成员变量和回调不变，旧原生 UI 测试照旧能点到。

## 不做
真实电网容量与负载竞争（G6.2）；船队页；仓库专业页（暂由货运区业务终端承担）；炉台 / 分选台的远程操作（Q30 要亲手）；新台词。
