# 成长内容、数值方法与真人试玩

状态：候选内容与待验证指标。此表不代表新工具、船型、订单已制作。对白只列触发位置，具体文本由用户编写。

本轮按完整对话修订：用户明确的工业港定位、交通/载具、有限评分与卖家博弈、真实轨道、分组分回收及液化补给是设计要求。具体会话长度、价格区间、材料配比与载具分类是助手建议，需验证，不能当作用户已定数值。

## 1. 一条能持续期待的工程链

每个节点同时给予新方法与新机会；已经学会的旧动作应该减少。下表不是强制线性关卡，玩家可用等效能力或采购完成所需工程。

| 节点 | 以前的困难 | 玩家完成的工程 | 获得的能力 | 接下来想尝试 |
|---|---|---|---|---|
| A 恢复回收能力 | 只能低效处理/单口排队 | 留住或采购设备并安装验收 | 实际可并行的回收设施 | 更完整地拆出高价值设备 |
| B 掌握整体取件 | 切碎快但损失价值 | 支承、断开接口、完整吊取 | 对应工具/工序资格与可用实物 | 接重载回收委托 |
| C 保存成熟工序 | 每艘重复同一套动作 | G4 实际录制并跨船验证 | 可授权的安全局部作业包 | 人去做新区域，机器做旧部分 |
| C2 港区交通恢复 | 无人机长途慢飞，现场互相隔离 | 乘坐接驳、驾驶小艇、靠泊释放无人机 | 已发现安全路线快捷通勤，站外轻型作业 | 亲自到加工区调试、到待泊区检验资产 |
| D 第一份工业产品 | 原料只值现货价 | 实际加工和质检交付 | 标准配方自动排产 | 用废料修一项真正有用的设施 |
| E 买对一艘船 | 只能被动挑少量委托 | 证据估价、产权、提货、作业 | 更多可见船源/估价经验 | 寻找目标设备或合适批次原料 |
| F 首次并行生产 | 炉子/装卸争功率 | 错峰/储能/供电工程之一 | 可靠的多区产能 | 同时做材料单和设备回收 |
| G 第一批合格补给 | 抽气只有安全成本 | 回收、分离、液化、储存、客户实际交接 | 对应产品和客户资格、成熟批次自动调度 | 针对航线需求采购气源、修储罐或提高供电 |
| H 站体开始代劳 | 每单手工派送补料 | 建立有权限边界的调度规则 | 成熟业务自动运转 | 选择更复杂工程而非多点按钮 |
| I 第二泊位 | 一艘新船占满所有时间 | 共享资源和异常接管验收 | 两项目真实并行 | 人工探索与成熟流程共存 |
| J 重载能力 | 整体总成超出现有能力 | 重载坞试验、能源/冷却工程 | 实际更大载荷与项目资格 | 勘验整艘远航者 |
| K 远航者与复航 | 港站无力承接大型星舰 | 消旋、危险处置、分阶段交付 | 完整转运环和大型商业服务 | 通关后专精自己的工业站 |

## 2. 作者内容怎样避免重复

需要不同“问题”，不是只增加船体长度与螺丝数量。每个主要船源/工程模板至少改变两项：
- 支承/受力关系；整体回收价值与切碎价值的取舍。
- 电、气、液的连通和实际隔离路径。
- 进入空间、局部几何、可用吊装方向。
- 已知/未知信息分布与检验价值。
- 产权边界、污染处置或交付规格。
- 当前站体能力对方法的影响。

### 首批内容组合建议

| 内容模板 | 重点问题 | 适合系统 | 避免的做法 |
|---|---|---|---|
| 熟悉小型作业船 | 低风险、能完整取件 | 首次市场比较、G4 复用 | 随机塞核心危险惩罚新手 |
| 补焊旧货船 | 几何和连接局部变化 | 检验与计划安全暂停 | 同型所有焊点每次全随机 |
| 有租赁设备的船 | 产权范围和合法去向 | 买船判断、证据 | 未披露却无法索赔的扣款 |
| 工业气体载具/罐架 | 介质、容器与回收经济性 | 气体业务 | 名字不同但内部全是空气 |
| 高价值整体总成 | 重载、限位、吊装姿态 | 工程成长、重载坞 | 直接降低质量让现有机吊得起 |
| 污染废料批次 | 原料品质与返工/降级 | 加工经营 | 买后临时抽签全报废 |
| 多买家同期限需求 | 电网、装卸、产能冲突 | G6 调度 | 每个都必须接，否则主线失败 |

已有 GR7 工程委托可以承载部分教学和成长；独立教学船继续独立，不把正式 GR7 合同重新包装成必做序章。

## 3. 平衡从实际收益和主动时长开始

### 先测基线

选择至少三类代表性工作：正常小单、完整设备回收单、重载/复杂工程单。分别测现金净利、库存变化、耗材、机器时间、真人主动时间与风险。用代表性正常单净收益 N 作为早期定价参考，不用开发者作弊资金测“买得起”。

N 不是全球唯一价格指数。加工利润还要扣原料机会成本、电力与物流；主动时长和设备占用不同，不能强迫所有路线每小时完全等收益。

### 候选价格区间

| 项目 | 初步参考 | 必须产生的实际差异 |
|---|---|---|
| 尝试一种工具/型号 | 约 0.3–0.7N | 一单后能试，而非看几小时商品页 |
| 常用出勤配置 | 约 1–2N | 遗失可补回，仍有携带取舍 |
| 早期中型修复 | 约 2–4N 等效价值 | 解决已见瓶颈，不能只涨售价 |
| 长期工程 | 分包报价，不固定套 N 倍数 | 付款节奏与新业务能力共同支撑 |
| 检验/外包 | 按范围/运输/质量风险标定 | 在部分订单中值得，在其他订单中可省 |

这些沿用“让新方法买得起”的方向，不是已定物价。若当前 N 不支持区间，应先找现金流与耗材问题，不能靠调高船价把人困在旧单里。

### 利润不能只看进账

结算分四栏：现金、保留/消耗资产、产能/时间、工程变化。示例：留下一台估值高的发电机可能使本单现金少，却完成供电修复；必须同时告诉玩家获得了什么，不能只显示负收益警告。

现货出售、订单履约和留作建设至少在若干明确情境中各自合理。设计不追求任何时候都三选一均衡；要避免从头到尾只有“先加工再卖”绝对正确。

## 4. 新增机制时同步减少旧负担

| 新系统 | 第一次亲自参与 | 掌握之后 | 仍需人工的情况 |
|---|---|---|---|
| 市场估价 | 看证据、算成本 | 保存筛选和报价偏好 | 新类型、异常报告、超预算购买 |
| 运输 | 比较路线与窗口 | 同路线在预算内派单 | 新载荷、推进能力不足、救援 |
| 熔炉 | 原料、取样、异常、实际交付 | 标准批次自动排产 | 污染、品质失败、设备异常 |
| 气体 | 样品、容器、处理路径 | 合规组分按保存规则处理 | 未知危险物、超限杂质 |
| 补料与仓储 | 设定保留量和权限 | 调拨/补货自动执行 | 稀缺设备、产权冲突、容量不足 |
| 第二泊位 | 授权工序和资源预算 | 安全工序独立运行 | 新结构、新危险、无法通过几何检查 |

让自动化系统自动重复错误不是成长。权限、输入条件与异常解释必须跟上。

## 5. UI 信息架构

运营总览只回答三件事：正在做什么、哪里需要我、下一步能建设什么。专业信息留在对应页面。

建议入口：
- 市场：船源/原料/需求/已签合同。
- 作业：泊位、计划、机器、警报和现场跳转。
- 生产：炉次、配方、质量、排产。
- 仓储货运：可用/预留/客户货、容量、装运。
- 能源：供需、储能、等待原因、优先级。
- 港站建设：钉选工程、设备/材料缺口、采购或自取路径。

同一个对象可以从多处进入详情，但操作状态只有一份。不能一边显示某批货“已预留”，另一个页面仍允许全量出售。

每个重要提示写成“对象 + 原因 + 可行处理”。例如“炉次等待供电：可用功率不足；可推迟装卸、使用储能，或保持排队”，实际数字取实时状态。不要只写红色“条件不满足”。

手柄焦点、改键、中英文、1280/1920 布局同步验收。工业终端视觉以文字、编号和工程图为主，但选择、预留、执行、暂停、失败必须有形状/图标/文字差异，不靠颜色单独传达。

## 6. 分阶段真人试玩

不能靠问“好不好玩”结束。观察实际决策与重复操作，记录出现时间、玩家原话和卡住原因；不把口头赞同当行为证据。

### G5 样片：一笔生意和一个工程目标

给玩家一个有限需求和一个可钉选修复目标，不指定来源路线。观察其看市场、看工程、看库存的顺序。

同时包含短接驳路线、小型作业艇原型与基础加工现场。玩家必须能实际抵达；不能由测试脚本移动位置或用所有功能都在同一终端来掩盖通行问题。

要回答：
1. 开工前能否解释为什么选这条来源？
2. 是否实际比较过至少两条可行路线？若没有，是信息难找还是一条明显无用？
3. 原料卖钱、加工、建设之间是否出现过真实犹豫？
4. 知道现金少了是因为保留资产，还是误以为系统扣钱？
5. 结束时能否说出下一单想尝试的具体方法？
6. 能否结合报告日期/范围和型号经验判断，而非只按评分高低买船？
7. 能否用接驳/小艇完成一次往返，是否比原先无人机长途飞行更方便？
8. 原料在当前任务中的实际加工与装运是否看得清，机械运动是否可信？

### G6 样片：产能冲突与独立业务

给两个可以选择接受的需求，供能/装卸资源不足以最快同时完成；提供已实现的可行替代。再允许连续完成两次相同成熟业务。

要回答：
1. 瓶颈原因在正常操作中是否看得见？
2. 是否理解至少两种处理方式的代价？
3. 第二次业务是否显著少点重复按钮？
4. 跨区移动是否让人放弃查看现场？
5. 不拆船完成生意是否仍觉得在经营同一个站？

另做一次完整过路船补给：从实际混合气回收开始，观察净化/分离、液氧生产与储存、靠泊和交付。记录玩家是否明白哪些物质有价值、为何可能不值得处理，以及供电/储罐如何影响报价与交期。若只完成混合气卖出，不算液氧补给试玩已验证。

### 六区现场与机械专项

让玩家自由走访，不先用讲解告诉其每栋楼是什么。观察能否从设备、物流和运行状态认出各区，能否找到可用接口、接驳点和自己的艇。

加工区专门观察粉碎咬料、残渣进入离心与排出、探头随钢液位置伸入/退出、压缸连续压实/保压/退回。记录哪个环节看起来像无关循环动画、跳变或物料凭空消失。画面精细不等于动作可信，两者分别检查。

### G7 样片：并行与长期项目

先用两艘普通船验证并行，再测试远航者一个可保存阶段。不要一上来用终局高负载掩盖基本 UI 问题。

要回答：
1. 玩家是否能判断当前更值得自己处理哪边？
2. 异常提示能否直接指向局部原因？
3. 共享设备有没有造成无意义往返/排队？
4. 退出、重载、恢复后是否知道下一步做什么？
5. 阶段交付是否让港站能力或世界状态发生可见变化？

## 7. 建议的观测指标

| 指标 | 正确测法 | 不能怎么冒充 |
|---|---|---|
| 重复劳动减少 | 同口径实际人工完成动作与主动耗时，正数 A 对 B，列明安全决策 | 机器切口细分计数对人工整次点击，或 0 对 0 |
| 经营选择 | 记录玩家查看/比较/采用的路线及原因 | 每次随便换三个按钮都算三个策略 |
| 升级价值 | 升级前后能完成的工作及实际流程变化 | 单看收入数字上涨 |
| 自动业务负担 | 每笔成熟业务人工介入次数与原因 | 后台失败全被忽略也算省心 |
| 长期动力 | 隔次游玩前后的具体目标与主动行为 | 单次问卷一句“可以”推断 60 小时留存 |
| 性能 | 有渲染、真实活动场景、墙钟帧时间 | headless 或固定模拟帧率写成稳定 60 FPS |

初次可由用户单人试玩给出问题；若增加其他测试者，样本与条件如实记录。没有足够样本不报百分比留存结论。

## 8. 调整准则

- 玩家只想刷旧合同：先查新路线的机会、反馈和成本信息，不先削弱旧合同逼其转型。
- 玩家把气体全排了：先查气量、处理成本和操作负担；小舱室本就不必盈利。
- 玩家永远外包：检查自有设备是否有独特优势与合理利用率；外包仍须保留。
- 玩家永远只买原料：检查拆船的完整设备价值、工程机会与亲手体验，不能凭空给买料加惩罚税。
- 玩家每次必须全检：检查低风险委托、报告可信度和检查价值；恢复可理解的信息选择。
- 六区都像任务清单：减少强制依赖，增加业务替代与可见现场成果。
- 玩家仍然不想离开船坞：检查通行、载具、现场细节和实际用途，不先追加必须跨区点按钮的任务。
- 液氧只剩库存数字：补上实际处理机构、低温容器、能耗变化、客户靠泊和交接；不以多一张销售页判定产业完成。
- 远航者变成碎片清理：扩大可保留总成与成熟作业包适用范围，保持实际载荷/碰撞；不能直接删掉剩余船体。

## 9. 对白与叙事触发清单

保留以下空位给用户：第一次留下设备修站、第一炉产品交货、首次购买废船、发现报告矛盾、动力区首次并行、首次合格补给、第二泊位首次接管、远航者勘验/消旋/核心阶段、转运环复航、KX-0 真相。

设计实现只提供事件 ID、触发条件、现场对象与重播规则；没有用户文案时使用简短系统状态，不代写角色长对白。
