# 96 号 拖船站精细化与进港预处理（2026-10-28）

## 用户原话
- “把港区拖船站整个区域的画面精度做上去：和主角无人机一样细致、丝滑；极高精度、惊艳；一眼看出每样东西干什么、什么状态、能拿它做什么。”
- 看样板后：“既然都说是拖船站了，为什么是在船外呢？……左边那个口是开着的，外面的船可以伸一半进来，先固定，然后再运到拆船站。……这龙门吊和推进器检修有何意义？”
- “a，还有自家的拖船也要开进来停靠”；“美工非常好……龙门吊的物理模拟都可以”。

## 布局（站房 60 × 28 m，侧视，地面 y = 26.8）
- **左墙**：上部拖船门（y 5–10.6，卷帘），下部船坞口（y 12.6–26.6，上下两扇门），中间墩柱上有状态灯。
- **下层左：船坞口**。拖回来的船停在 1 号泊位 = 船坞口。高度 ≤ 13.6 m 的船船尾伸进站内（最多 19.5 m）；更高的船停在原来的露天泊位，不做预处理。龙门吊（跨度 2–22 m，SWL 40 t）跨在上方。
- **上层右：拖船甲板**（x 22.6–51.8，y 10.8）。T-01 在近道、T-02 在远道（远道画得暗一点、高一点，表示前后两条道，互不穿过）。每个泊位有服务立柱（加注臂旋转座、充电插座），尾部吊舱下方有甲板舱口。
- **下层右**：吊舱检修台（两台升降台 + 备用鞍座 A + 检修鞍座 B + 横移滑车 + 甲板下吊挂的无损检测探头）、MMH 储罐（液位、视镜、泄压阀、爬梯、底部输送泵）、零件箱（能看到里面的阀件 / 密封圈 / 紧固件 / 线束）；右上是备件架（喷管、缆绳盘、电池模块带指示灯、阀块）。
- **推进剂总管**：储罐 → 地面 → 立管 → 软管卷盘（船坞口上方）；另一路上甲板接两个泊位的加注臂。
- 右墙的无人机门和两台终端不动；碰撞框改成检修台 / 备件架 / 甲板。

## 作业流程（`scripts/tug_works.gd`）
所有机器都是“执行器追目标”：加速、提前刹车、准确停住；吊载会随小车起停轻微摆动（阻尼摆，最大 4°）。作业写成步骤表，每一步设定目标并等它到位。
1. **废船进港预处理**（废船停进船坞口、拖入镜头结束后开始，约 52 秒）：系泊臂夹住船体 → 软管接上船尾排放口开始抽料（和后面几步并行）→ 龙门吊从夹具架取推船夹具，绕过船顶，装到船尾 → 小车激光扫描整段船体 → 抽料完成，写入 `asset.prep = {drained, m3}`，抽出量进 `Career.data.tug_prop` → 软管收回，龙门吊停回原位。
2. **拖船回港**：拖船门打开，拖船主推进器开着飞进来，快到泊位时用反推刹车；停好后接上加注臂（从储罐出料）和充电线（按真实充电进度）。
3. **换吊舱**：甲板舱口打开 → 升降台上去托住尾部吊舱 → 降到检修台 → 滑车把旧吊舱送到 B，把 A 上的备用吊舱送上升降台 → 升上去装好 → 舱口关闭。B 上检修 45 秒（喷管烟灰随进度褪去），修好后滑回 A 当下一个备用。没有备用吊舱时，下一艘回港的拖船要等。
4. 读档时，已经预处理过的废船直接显示为处理完的状态（夹具在船尾、系泊臂夹着）。

## 真实影响（Q11 B）
- `systems.gd`：开工时，经过船坞口预处理的船，所有 `fluid == "fuel"` 的推进剂体积乘以 (1 − 抽走比例)。拆的时候起火、爆燃的风险相应降低，但不会消失。
- `TugYard`：储罐上限 8 m³；推进剂按每 m³ $4,000 计价。`Charter.prop_from_tank / prop_cash`：接包机单时推进剂先从储罐扣，不够再花钱；贸易港包机单的说明行会写“站内储罐抵 $X”。
- 拖船回港加注从储罐出（每次 0.25 m³）。

## 画法与性能（`scripts/tug_station_art.gd`、`scripts/mesh_pen.gd`）
- 每台会动的机器（小车、吊钩组、推船夹具、吊舱、拖船、升降台）都用 `MeshPen` 一次建成网格，之后每帧一次 `draw_mesh` 摆放（约 0.2 µs）。静态部分按“有电 / 细节等级 / 站等级”缓存成一个网格，状态不变就不重画。
- 每帧现画的只有细线、少量 `FastDraw` 圆和铭牌文字。
- 废船船尾在站内这一层画（按左墙内侧裁切）；`tow_traffic.gd` 在站外只画到墙面，不再穿模。
- 外壳（`port_art.gd`）：左墙画出拖船门和船坞口（深色开口加警示斜纹，门的开合跟着状态机走），两盏状态灯，屋顶信标在作业时旋转。原来左墙外的车库泊位已删掉。

## 悬停卡（`scripts/facility_card.gd`）
屏幕空间的通用设施卡（层级 25，在 HUD 上面）。指针停留 0.25 秒后淡入，卡片保持在屏幕内，不抢输入。拖船站提供 8 张卡：船坞口、龙门吊、T-01、T-02、检修台、储罐、备件架、零件箱。每张卡分“用途 / 现在 / 你能做”三行，“现在”一行跟铭牌灯同色。其他区以后只要提供 `items` 就能用。测试用 `probe` 点代替鼠标，绝不移动鼠标。

## 音效（只用真实录音）
- 新增 `crane_loop.ogg`：Sonniss GDC 2019 · 3maze Electric Motors · `motor_med_011.wav`，截 3.2 秒，交叉淡化成无缝循环（`tools/tug_audio.py`）。音量和音高跟随龙门吊、升降台、滑车的实际速度。
- 复用游戏里已有的录音：吊钩 / 升降台停住 `winch_brake`，系泊臂夹上 `clamp`，软管接上 `hose_on`，舱口开启 `hatch`，门关到位 `roll_lock`，输送泵 `pump_loop`。
- 只在无人机进入拖船站、或在站外 30 m 以内时才响。

## 测试
- `tests/tug_station_probe.gd`（有画面）：站内全景 / 近景 / 换舱和预处理全过程每 7 秒一张 / 悬停卡 / 外观；1080p 帧时间。
- `tests/tug_prep_check.gd`（headless，11 项）：GR-7 进口、CH-110 不进，52 秒处理完，抽走 40%，储罐增量，开拆时看到抽走比例，包机先扣储罐，高船不抽。
- 已更新：`tug_garage_check`（10 项，拖船飞出飞进与换吊舱）、`tow_in_check`（1 号泊位带船型）。通过：`interiors_check` 25、`tug_yard_check` 19、`yard_route_check` 23、`yard_skip_check` 9、`business_check` 36。
- `contents_check` 有 1 项“水箱切开放水”失败。本次只改了 fuel 体积，而且只对预处理过的船生效，按逻辑与此无关，但还没有和改前版本对比确认。

近景 P99 16.93 ms 略超 16.67 ms 的红线；机器负载波动大，需要在安静的机器上复测。

后来同一台机器同时开着 7 个 Godot 进程（其他会话在跑测试），整帧数据失真：同一次运行里把拖船站和接驳车都关掉，基线也有 18–19 ms。所以改成直接量拖船站自己的开销（`district_interiors.tug_tick_us / tug_draw_us`）：状态机原来 420 µs/帧，把每帧遍历存档改成每帧取一次、每 0.25 秒查一次船坞口、悬停卡每秒最多重建 10 次之后，降到 143 µs/帧；动态部分的绘制命令约 0.55–0.63 ms/帧。两项都是在高负载下测的。发布红线要等机器空闲时再复测确认。

## 待办与已知限制
- 高于 13.6 m 的船不进船坞口，也不做预处理（物理上塞不进）。
- 拖船飞进飞出、换吊舱的过程只在站内可见；站外只看到拖船门开关和指示灯。
- 拖船进出没有专门的音效（库里能找到的太空船飞过声都是合成的，没用）。
- 运行时偶发 “Parameter mesh is null” 报错，不是拖船站的网格造成的，已告知接驳车会话排查。
